# Next.js on Vercel, despite stronger Python fluency on the team

The stack is Next.js (App Router) with TypeScript and Tailwind, deployed on Vercel, with server routes fronting the Anthropic API and the code execution service. Progress is held client-side in a single serializable state object rather than in a database, and there is no authentication.

This was chosen over FastAPI even though Python is the stronger language here, for two reasons: a single deploy target avoids standing up a separate API purely to keep the Anthropic key server-side, and the implementation is being generated by an LLM, which favours the framework with the most consistent representation in training data over the one the author types fastest. The stated focus for this hackathon is conceptual design rather than hand-writing code, which is what makes the tradeoff acceptable.

Two consequences worth knowing. Debugging at speed is harder for the author, mitigated by keeping prompts and the phase state machine in isolated, plainly-written modules. And holding progress client-side hard-blocks the peer collaboration and PR review stretch goals, which need shared server state — that door is closed by this decision, not merely deprioritised.
